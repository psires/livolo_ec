# MG21 output toggle trial — 2026-10-24

Both outputs of development switch `46715621` completed an individually commanded
OFF → ON → OFF cycle through the deployed MG21 gateway. The original state was
both OFF; the final native report also confirms both OFF. The Nordic nRF52840
independently captured the baseline, all four state transitions, and their
application acknowledgements on channel 11.

- [Complete API and decoded RF evidence](mg21-toggle-20261024.json)
- [Nordic capture](../../captured/development/mg21-toggle-20261024-nrf52840.pcapng)
- Gateway `2a992b12`, tag `a7`; ZB-GW04 v1.2, MG21 firmware 0.2.
- Live `livolod` HTTP commands; MQTT used only for read-only state refresh.
- No firmware update, daemon restart, pairing, or registry change during this trial.

The first baseline report preceded the first output command. The duplicate
baseline report arrived during the first command and was correctly ignored as
command confirmation. Each set confirmation matched the requested mask, new
token, full output state, and advancing report counter. The unselected output
remained OFF throughout. Commands were separated by two-second holds after
confirmation. Existing host retries produced 11 on-air command copies for four
logical requests; all four logical requests confirmed.

API-request-to-native-confirmation times were 1,083, 61, 947, and 476 ms. Nordic
saw the first matching reports 1,047, 25, 712, and 440 ms after each first on-air
command. For output 2 ON, Nordic saw a report repeated about 200 ms later; the
later report was acknowledged and delivered to the host.

Final restoration was reported at **14:43:38 UTC / 16:43:38 CEST**, counter 117,
token `4c`, mask 2, full state bits 0. The daemon remained ready, and a follow-up
API check at 14:44:13 UTC still held that same OFF/OFF report. This follow-up is
a check of saved live-daemon state, not an additional fresh RF observation.

## Capture and limitations

The 256-frame capture contains 46 relevant EC frames, all with valid application
checksums. The before/after adapter snapshots recorded no additional RX-log,
UART, or radio-drop counters and no ACK failures. They recorded 31 TX requests
and 30 TX completions; the reason for the one non-completed transmission was not
collected. All four requested state changes nevertheless have matching native
reports independently captured on air.

Fresh-state acquisition is intermittent: an initial HTTP refresh was rejected
because that action is not exposed by the web API; the next MQTT refresh timed
out. In the successful capture, the first two MQTT refresh requests timed out
and the third returned the fresh OFF/OFF baseline. None of those failed baseline
attempts sent output commands. No protocol or software changes were made to
work around this behavior.

This verifies real-device protocol behavior and device-reported output states.
No external electrical measurement or visual observation of the connected load
was taken. One ON/OFF cycle per output is a functional smoke test, not a
long-term reliability qualification. Raw pcaps, sniffer logs, the bounded trial
script, and the earlier failed baseline attempts remain under
`/home/sfires/livolo-ec/mg21-port/evidence` and `.local/mg21` locally.
