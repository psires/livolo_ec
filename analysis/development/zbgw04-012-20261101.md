# ZB-GW04 v1.2 firmware 0.12 qualification — 2026-11-01

The reconnected ZB-GW04 v1.2 now runs the current gateway release at **460800**,
including DMA UART reception, MCU heartbeat/query/output transactions and
phase-stamped automatic ACKs. The board profile now enables `EC_AUTO_ACK_PHASE`,
as Sonoff already did. Timing and retry limits were not changed. The preserved
Gecko **1.9.2** bootloader still uses **115200**; only the application GBL was
flashed. The board was identified by its existing UART v3 `board=zb-gw04-1v2`
response before flashing, rather than inferred from CH340 USB identity alone.

## Results

| Check | Result |
| --- | --- |
| Non-transmitting UART v3 conformance | 12/12 checks, including 256 peers, leases, duplicate IDs and session guards |
| Exact UART integrity at 460800 | 6,000/6,000 requests; no retries, mismatches or timeouts |
| Live observation | 601.322 seconds; one radio session, no Docker restart or daemon reconnect |
| Fresh control run after asking user to leave controls untouched | **24/24 confirmed**, 8/8 per physical output across the one- and two-gang switches |
| Fresh-run transmission budget | 23 commands used two attempts; one used three attempts with only two successful sends (one busy-channel attempt) |
| Independent capture of fresh-run output sends | **48/48 successful sends captured** |
| Fresh-run retry interval | Median **200.010 ms**, range 199.711–200.068 ms |
| Fresh-run absolute heartbeat-grid error | Median **0.057 ms**, maximum **0.351 ms** |
| Automatic ACKs in live window | 86 captured, all phase-stamped; 84 matched incoming packets, median reply delay **1.859 ms**, maximum 2.578 ms |
| Transport/loss diagnostics | No new UART errors, overruns, DMA errors/resyncs, input errors, RX/UART/radio drops |
| Sonoff isolation | Explicitly disarmed; TX and ACK transmission counters both unchanged |

The intentional malformed-line conformance check leaves `input_errors=1`.
Integrity and live comparisons verify **zero increments**, rather than claiming
that cumulative counter was zero. The UART integrity run also verifies zero
radio transmissions while disarmed. Native C core tests passed: 33 ACK-phase,
62 scheduler and 26 output-grid cases, including inherited common cases.

The first control block was 20/24; a subsequent settled block was 24/24. The user
then confirmed having used physical/app controls during testing. These earlier
blocks are preserved as observations, **not isolated hardware reliability
estimates**. The final 24-request run began after that disclosure and a fresh
request to leave controls untouched. It confirmed every command and stopped
sending after each valid matching state report. The first run included native
reports with unexpected mask/token fields; user actions and settling cannot be
separated retrospectively. The report does not attribute those four unconfirmed
transactions to defective hardware or firmware.

Across all three blocks Nordic captured 168 of 170 reported successful output
sends. Both missing packets were outside the final isolated block. The raw
capture contains 7,327 records, 3,595 decoded EC packets and no bad EC checksums.
No original EC gateway heartbeats were heard in the live window; this does not
exclude other interference. The 59 measured local heartbeat intervals have a
10,000.420 ms median; one delayed boundary and the following recovery interval
are retained in the data (10,025.889 / 9,974.930 ms), rather than hidden as jitter.

## Final deployment

Docker remains the only daemon/UART owner on 10.1.1.21. Its image is unchanged:
`sha256:a465e5bdd2542b52c38b70537a43fecc6ecfa1d2ec60d989c4f243ab2f5c7016`.
Only `LIVOLO_SERIAL_DEVICE` in `/opt/livolod-docker/.env` changed to
`/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0`, mapped to `/dev/livolo` in the
container. Configuration JSON, Compose YAML and daemon environment bytes are
unchanged. The authoritative database stays
`/opt/livolod-docker/data/state.sqlite3`; both device registrations remain intact.
The native `livolod.service` stays stopped/disabled.

**ZB-GW04 is left active; Sonoff remains disarmed.** Both switches were online,
MQTT connected and pairing disabled at final verification. The final control
sequence restored its starting state: one-gang ON and both two-gang outputs ON.
The user was then told normal use could resume. Sonoff is still USB-powered;
“off” for this test means its gateway RF transmission and automatic ACKs are
disabled, verified by counters, not a physical USB power cut.

Use `sudo livolodctl stop` before any direct radio maintenance and
`sudo livolodctl start` afterward. Before returning to Sonoff, stop Docker,
disarm ZB-GW04, restore the Sonoff serial mapping and recreate the container.
Do not enable both radios with the same network identity.

Private pre-test backups are under
`/home/sfires/livolo-ec/zbgw04-012-20261101/private-backup` (restricted access).
Build sources, BIN/GBL and original logs are in that run directory on the Pi;
local copies are under `.local/zbgw04-012-20261101`. No signing keys, credentials
or database contents are included in this report.

## Scope and evidence

This qualifies the **specific ZB-GW04 v1.2 board** for a bounded 0.12 test; it is
not proof of indefinite reliability or compatibility with other CH340/MG21
adapters. The old reply-truncation problem did not reproduce in this run.
Read-only query reliability remains tier 3; no query sweep or retry-policy change
was introduced. Unsolicited state reports remain the primary state source.
