# TI CC2652P firmware 0.12 qualification — 2026-11-01

The existing cod.m CC2652P module now runs release **0.12 at 460800 baud**.
The shared MCU heartbeat, query and aligned output transaction implementation
was built for TI's **65,536 Hz** timer; automatic ACK phase stamping is now
enabled in its Makefile. Authoritative network state remains on the Pi.
Output bounds remain six attempts/four seconds. Query timing and retry bounds
were not changed or swept in this test.

The signed `.ecupd` was transferred through the running 0.7 application,
activated in software, then confirmed by Docker daemon 0.12 after it restored
the volatile radio configuration. **No GPIO pulse, button press or ROM-loader
entry was needed.** The signed bootloader remains **0.2**. The application BIN
is 69,208 bytes and fits the 98,304-byte application slot; bootloader and CCFG
were not flashed. This is the identified **CC2652P, not CC2652P7**.

## Results

| Check | Result |
| --- | --- |
| Dry UART protocol conformance | 12/12 checks; no RF transmissions |
| Scheduler/lease dry check | Passed at 65,536 Hz, including cancellation and expiry |
| UART integrity at 460800 | 6,000/6,000 exact requests; no retries, mismatches or timeouts |
| Continuous live observation | 600.532 seconds, one radio session, no Docker restart |
| Initial / settled controls | 20/24 then 24/24 confirmed; settled block 8/8 per output |
| Settled attempts | 23 commands at two attempts, one at three; bounds unchanged |
| Settled output capture | 48/49 reported successful sends captured |
| Settled retry spacing | Median 200.007 ms; 199.866–200.713 ms |
| Settled absolute grid error | Median 0.145 ms, maximum 0.777 ms |
| Automatic ACK capture | 56 captured, all phase-stamped; 54 matched incoming packets |
| ACK response delay | Median 1.881 ms, maximum 2.964 ms |
| Loss/transport increments | RX/UART/metadata drops, input errors, RX sequence gaps and ACK failures all zero |
| Other radios | Sonoff and ZB-GW04 TX/ACK counters unchanged while disarmed |

For comparison, the clean ZB-GW04 block was 24/24 confirmed with 48/48 sends
captured, median retry 200.010 ms, median grid error 0.057 ms and maximum
0.351 ms. TI's measured grid is slightly less tight but remains below 1 ms
in this settled sample; these separate runs do not isolate hardware effects
from changes in RF conditions.

Across both TI blocks Nordic captured 105/114 reported successful output sends.
One confirmed initial transaction's exact retained report was absent from Nordic;
its valid matching report is preserved in the MCU result. Missing heartbeats
and packets limit air-only conclusions. The capture contains 7,377 records,
3,350 decoded EC frames and no bad EC application checksums.

`invalid_rx` increased by 1,920 in the daemon. The same counter increased by
4,710 in the previous ZB-GW04 observation. It combines unsupported EC frames
and malformed RX envelopes. Replaying Nordic's live-window packets through
the host decoder yields 2,776 **Unsupported EC frame** rejections and no other
decode errors, alongside 2,293 accepted frames. This establishes substantial
unsupported traffic, not a one-to-one explanation of every TI rejection.
Do not treat this aggregate as a hardware UART error count.

The intentional malformed-line conformance test left `input_errors=1`.
Subsequent integrity/live checks compare increments. TI exposes software loss
counters but does **not** expose the MG21 hardware UART overrun/DMA/radio-loss
counters, so their absence is not evidence of zero hardware errors.
Native C tests passed: 22 TI output-grid cases including inherited common
checks, and 33 ACK-phase cases. TI-specific checks cover fractional 200 ms
slots across 32-bit timer wrap, exact-report cancellation and ACK phase stamps.

## Early control failures

The first control block confirmed **20/24**. The later block confirmed **24/24**,
matching the clean ZB-GW04 result. The user was asked to leave buttons/app
controls untouched for both TI blocks. Unlike the early ZB-GW04 run, user
interference has not been reported here; it cannot be used to dismiss these
four failures. Improvement after settling is an observation, not proof of the
cause. The capture and all failed transactions are retained.

The first two requests targeted the one-gang switch (ON then OFF). Nordic
captured all nine reported successful sends across those requests, but no native
state reports in either transaction window. The other two unconfirmed requests
were two-gang output 2 ON and output 1 ON. Each produced a native report with
the requested physical-state bits but the **previous command's token** (240
instead of 242, and 247 instead of 249). The exact transaction matcher correctly
left those requests unconfirmed. This does not prove the physical outputs failed
to change. Nordic captured four of six reported successful sends in the latter
case; missing sniffer frames do not establish whether the switch received them.

A Nordic-received report is not necessarily a TI-received report. Cancellation
checks therefore use the exact raw report retained by the MCU when Nordic
captured it, rather than requiring the MCU to stop on an earlier report heard
only by the independent sniffer. No retry budget was increased to obtain the
settled result. State-query reliability remains tier 3 by the user's decision.

## Deployment and scope

Docker remains the sole daemon/UART owner on 10.1.1.21. The image, configuration
JSON, Compose YAML, daemon environment and authoritative database location are
preserved. Only `LIVOLO_SERIAL_DEVICE` in `/opt/livolod-docker/.env` changed from
the ZB-GW04 by-id path to **`/dev/ttyAMA0`**, mapped to `/dev/livolo` in Docker.
The native `livolod.service` remains disabled and stopped.

TI is left active. Sonoff and ZB-GW04 remain USB-powered but explicitly
RF-disarmed; their TX and ACK counters did not change. To return to either,
stop Docker with `livolodctl stop`, disarm TI, change the serial mapping, then
`livolodctl start`. Do not arm two adapters with the same network identity.
Both test registrations remain intact, pairing is disabled, and MQTT is
connected. The controlled sequence restored one-gang OFF / both two-gang ON;
normal use was allowed afterward during the passive observation.

This is bounded qualification on one module and two devices, not a long-term
or large-network reliability guarantee. The initial failures remain a handover
or RF follow-up item. Absence of original EC heartbeats does not establish a
quiet RF environment: other switches were still transmitting.

Restricted pre-test configuration/database backups remain under
`/home/sfires/livolo-ec/ti-012-20261101/private-backup`. Build artifacts and logs
are in that run directory; local signed artifacts are under
`.local/ti-012-20261101`. The signing private key stayed local and is excluded
from the evidence.
