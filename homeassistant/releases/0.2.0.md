Native Home Assistant integration 0.2.0, published from commit
`6fe41cbdc909a6497776202b3eeae088655b9908`.

### Changes since 0.1.1

- Standard HA firmware update entity backed by the daemon's durable maintenance
  jobs. It tracks updates started from HA or the web UI and waits for verified
  completion. Lost responses never cause an automatic second flash.
- **Configure → Detect a switch (experimental)**: select an observed switch,
  review its one- or two-output profile, then register it. Expired, conflicting or
  changed evidence requires a fresh selection. Manual configuration remains
  available; registration and physical pairing are separate actions.
- Matching daemon profile validation and browser setup controls, plus an
  emergency firmware maintenance CLI and board-specific recovery instructions.

### Installation and upgrade

Back up your HA configuration and the daemon's current persistent state. Download
`livolo-ec-ha-0.2.0.zip`, verify it with `SHA256SUMS`, and install its
`custom_components/livolo_ec` directory in your HA configuration directory.
Restart Home Assistant. Existing network identity and configuration entries are
retained; do not replace the daemon database with an older copy.

Use the matching daemon source from this release for detection and firmware-job
support. Older daemons retain manual switch setup but cannot provide the new
capabilities. The integration ZIP includes its client; it does not run the daemon.
The companion app archive is an **aarch64 source build context**, not a prebuilt
image or a Supervisor repository. These are manual-install assets, not a
configured HACS/Marketplace distribution. See [installation instructions](https://github.com/psires/livolo_ec/blob/ha-0.2.0/homeassistant/README.md).

### Versions and limits

Integration, companion app and client are **0.2.0**. Daemon and radio firmware
remain **0.12**, with native API revision 1 and UART revision 3. Qualification
targets HA Core **2026.10.4**.

The firmware catalog is **empty**. No qualified radio payloads are bundled or
attached, so firmware installation remains unavailable until a compatible,
trusted bundle is supplied and the actual deployment is qualified. TI and both
MG21 update backends are implemented; integrated Nordic DFU remains disabled.
No hardware was flashed or deployed as part of publishing this release. See
[firmware recovery](https://github.com/psires/livolo_ec/blob/ha-0.2.0/docs/FIRMWARE_RECOVERY.md).

Detection recognizes the two observed one-/two-gang pairing signatures; it is
not universal model discovery or device authentication. Unknown and legacy
variants require manual configuration. These new detection paths have simulated
and protocol-fixture coverage, not new live commissioning qualification.

Validation: **225 host tests, 65 HA/client/packaging tests and 18 browser tests**
passed, plus source documentation/format checks and HA integration validation.
Project-owned code remains BSD-2-Clause; external tools and dependencies retain
their own terms. `release.json` records exact source/component versions, and
`SHA256SUMS` covers all supplied assets except the checksum file itself.
