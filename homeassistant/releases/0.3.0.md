Livolo EC for Home Assistant **0.3.0** adds shared firmware preflight to the
native integration and daemon app. The daemon compatibility version is **0.13**;
the native API remains revision 1 and the radio protocol remains UART 3.

### Install and update

Use the [HACS/Marketplace integration channel](https://github.com/psires/ha-livolo-ec)
and the [HA app repository](https://github.com/psires/livolo_ec). They are separate
updates. Retain your existing integration entry and restart HA after updating
the integration files. A local development app has a different Supervisor
identity; adding the repository does not migrate its data automatically.

The manual `livolo-ec-ha-0.3.0.zip` here extracts into the HA configuration
directory. The integration-channel `livolo_ec.zip` has a different, component-root
layout for HACS/Marketplace. Keep the respective installation methods separate.

### Firmware preflight

- **Configure → Check firmware update (read-only)** shows the exact candidate,
  board, installed/target versions and blocking checks without starting a job.
- HA's standard firmware update action obtains fresh matching preflight evidence
  before submitting the existing durable installation request.
- The daemon's Web UI uses the same preflight contract and invalidates stale
  evidence when the candidate, radio state or connection changes.
- Older daemons keep switch control, but firmware installation requires the new
  preflight capability. An uncertain installation response is observed through
  its original job ID; it is not automatically replayed.

Software installation does not flash a radio. The public default firmware catalog
remains empty; locally prepared 0.13 trial artifacts and hardware qualification
have separate scope. Routine updates require an exact-board compatible artifact
and available backend. Emergency CLI recovery and its prerequisites are documented
in [FIRMWARE_FLASHING.md](https://github.com/psires/livolo_ec/blob/ha-0.3.0/docs/FIRMWARE_FLASHING.md).
