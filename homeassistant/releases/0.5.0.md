Livolo EC for Home Assistant **0.5.0** adds automatic pairing, clearer firmware
catalog diagnostics and independent daemon software version reporting. The
coordinated app contains daemon **0.14.0**, targeting radio compatibility **0.13**,
native API revision 1 and UART protocol 3.

### Changes

- Press **Pair new device** on the existing Livolo EC gateway, then put one
  supported switch into pairing mode. Status and **Cancel pairing** share the
  daemon's bounded session with Web and CLI.
- Registers the child device and outputs under the existing network; confirmed
  pairing sends a notification linking to the device. No duplicate integration or
  Discovered card is created; detection alone is not successful pairing.
- **Radio firmware status** explains missing/unusable catalogs and unavailable
  candidates. When a previously available offer is withdrawn because its catalog
  becomes unavailable, an actionable Repair directs administrators to catalog
  setup. Ordinary switch control remains available.
- Diagnostics distinguish daemon software version from firmware compatibility.
  Existing entity/device identifiers and firmware admission checks are retained.

### Install and upgrade

Use the [HACS/Marketplace integration channel](https://github.com/psires/ha-livolo-ec)
and [HA app repository](https://github.com/psires/livolo_ec). Update both software
components, preserving the integration entry and persistent configuration/data.
Restart HA after replacing integration files. Finish active commissioning or
firmware operations before updating the app. Preserve trusted local catalogs.

The manual `livolo-ec-ha-0.5.0.zip` extracts into the HA configuration directory.
The integration channel's `livolo_ec.zip` instead has component files at its root
for HACS/Marketplace. See the [pairing guide](https://github.com/psires/livolo_ec/blob/ha-0.5.0/docs/PAIRING.md)
and [versioning guide](https://github.com/psires/livolo_ec/blob/ha-0.5.0/docs/VERSIONING.md).

### Scope

This is a software-only release. The public firmware catalog remains empty and
no radio firmware is bundled or flashed. Existing exact-board limits and local
firmware qualification still apply; software checks add no physical qualification.
The app image supports ARM64; AMD64 containers remain future work. Project code
remains BSD-2-Clause and external dependencies retain their own licences.
